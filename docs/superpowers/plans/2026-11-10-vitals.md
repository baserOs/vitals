# Vitals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only macOS menu bar app showing CPU, GPU, memory, temperatures, fan speeds, power and battery on an Apple Silicon MacBook Pro.

**Architecture:** One Swift package. `VitalsCore` reads hardware through small single-purpose sources and publishes immutable `Snapshot`s from a `Sampler`. `VitalsApp` is a SwiftUI `MenuBarExtra` that only renders snapshots. `vitals-probe` dumps everything the core can read, for filling in the sensor table.

**Tech Stack:** Swift 5.9+, SwiftUI, Swift Charts, IOKit, SMC, IOReport and IOHIDEventSystemClient (private, declared in a C header target), XCTest.

**Spec:** `docs/superpowers/specs/2026-11-10-vitals-design.md`

## Global Constraints

- macOS 14 or later, Apple Silicon only.
- Read-only: no SMC write call exists anywhere in the code. No root, no helper, no `sudo`.
- Builds with `swift build -c release` and Xcode Command Line Tools. No Xcode project, no third-party dependencies.
- `LSUIElement` app: no Dock icon.
- Lightness target: under 1% average CPU and under 60 MB memory at the 2-second default refresh.
- A failing source returns `nil` or `[]`; it never throws and never blocks other sources.
- Views read `Snapshot` and history only; they never call a source.
- **Where things run:** code is written in a Linux container with no Swift toolchain. Every `Run:` step executes on the Mac. Without Mac access, the "verify it fails" step is skipped and all tests of a task are run together at the next checkpoint (marked **CHECKPOINT**), where the person pastes the output.

## Changes made during execution

These replace the matching parts of the tasks below.

- **Delivery.** The app is built by GitHub Actions (`.github/workflows/build.yml`) on a macOS runner and published as `Vitals.zip` on the `latest` release. Checkpoint A is that workflow run. Checkpoints B and C use the downloaded app.
- **Diagnostics.** The probe's logic lives in `VitalsCore/Diagnostics.swift`. `vitals-probe` prints it, and Settings has a "Copy diagnostics" button, so no Terminal is needed.
- **C wrappers.** `CVitals` contains real C code (`vitals.c`) exposing `vitals_smc_*`, `vitals_hid_*` and `vitals_energy_*`. Swift never sees the private Apple declarations. `SMCClient`'s Swift interface is as planned.
- **Windows.** The dashboard and settings are AppKit windows opened by `WindowManager`, not SwiftUI `Window` and `Settings` scenes, which would open at launch or fail to come forward in a menu-bar-only app.
- **Process list.** The sampler turns process collection on by asking, after each sample, whether the popover or a window is on screen. Views do not set it.
- **Memory.** "Used" is app memory (internal minus purgeable) plus wired plus compressed, to match Activity Monitor.
- **Target name.** The app's target is `Vitals` with sources in `Sources/VitalsApp`, so the binary is named `Vitals`.

## Review Focus

1. **Wake from sleep.** A long gap between samples makes delta-based CPU % and watts spike. Expected: a delta whose elapsed time exceeds 3× the interval is discarded. Test in Task 2 (`SampleGap`).
2. **Fans stopped.** MacBook Pro fans sit at 0 RPM when idle, below their stated minimum. Expected: shown as 0 rpm, fraction 0, not "not available". Test in Task 2 (`FanReading.fraction`).
3. **On battery.** Adapter watts do not exist. Expected: `nil`, rendered as "–", never "0 W". Test in Task 2 (`Format.watts(nil)`).
4. **Dead and duplicate sensors.** Unpopulated SMC sensors read exactly 0, and the same sensor can arrive from SMC and HID. Expected: values ≤ 0 dropped; duplicates by key keep the first. Test in Task 2 (`SensorCatalog`).
5. **Process churn.** A process can exit between listing and querying, and a multi-threaded one exceeds 100% CPU. Expected: the vanished one is skipped, and values above 100% are shown as-is. Covered in Task 3 by code review and at Checkpoint A, since it needs live processes.

### Task 3: Hardware sources

**Files:**
- Create in `Sources/VitalsCore/`: `CPUSource.swift`, `MemorySource.swift`, `GPUSource.swift`, `HIDSensors.swift`, `TemperatureSource.swift`, `FanSource.swift`, `IOReportReader.swift`, `PowerSource.swift`, `BatterySource.swift`, `ProcessSource.swift`

**Interfaces:**
- Consumes: everything from Tasks 1 and 2.
- Produces — each a `final class` with `init` and one method:

```swift
CPUSource().read() -> CPUReading?                       // first call returns usage 0 (no previous ticks)
MemorySource().read() -> MemoryReading?
GPUSource().read() -> GPUReading?
TemperatureSource(smc: SMCClient?).read() -> [TemperatureReading]
FanSource(smc: SMCClient?).read() -> [FanReading]
PowerSource(smc: SMCClient?).read(interval: TimeInterval) -> PowerReading?
BatterySource().read() -> BatteryReading?
ProcessSource().read(limit: Int) -> [ProcessReading]    // top `limit` by CPU, then top `limit` by memory, merged without duplicates
HIDSensors.read() -> [(name: String, celsius: Double)]
IOReportReader(group: String)?.sampleDelta() -> [(channel: String, unit: String, delta: Double)]
```

- [ ] **Step 1: `CPUSource`** — `host_processor_info(PROCESSOR_CPU_LOAD_INFO)`; keep previous `CPUTicks` per core; `CPUMath.usage` per core; deallocate the returned array with `vm_deallocate`. Core kinds from `sysctl hw.perflevel0.logicalcpu` (performance) and `hw.perflevel1.logicalcpu` (efficiency); efficiency cores have the lowest indices on Apple Silicon. Load average from `getloadavg`.
- [ ] **Step 2: `MemorySource`** — `host_statistics64(HOST_VM_INFO64)` × page size. used = active + wired + compressed; cached = purgeable + external; swap from `sysctl vm.swapusage`; pressure from `kern.memorystatus_vm_pressure_level` (1 normal, 2 warning, 4 critical).
- [ ] **Step 3: `GPUSource`** — iterate `IOAccelerator` services, read `PerformanceStatistics["Device Utilization %"]`, divide by 100.
- [ ] **Step 4: `HIDSensors` and `TemperatureSource`** — HID: match `PrimaryUsagePage 0xff00`, `PrimaryUsage 5`; name from the `Product` property. SMC: once at init, collect keys that start with `T` and have type `flt `; read each per sample. Merge SMC first, then HID (key = `"hid:" + name`, group by `describe`), then `SensorCatalog.clean`.
- [ ] **Step 5: `FanSource`** — count from `FNum`; per fan `F<n>Ac`, `F<n>Mn`, `F<n>Mx`. Returns `[]` when `smc` is nil or `FNum` is missing.
- [ ] **Step 6: `IOReportReader` and `PowerSource`** — subscribe to group `"Energy Model"`; keep the previous sample; `sampleDelta` returns per-channel deltas. CPU watts = channel `"CPU Energy"`, GPU = `"GPU Energy"`, each through `EnergyMath.watts`; discard when `SampleGap.isUsable` is false. System watts from SMC `PSTR`, adapter from `PDTR`; a missing key or a value ≤ 0 for the adapter gives `nil`.
- [ ] **Step 7: `BatterySource`** — `AppleSmartBattery` registry properties: `CurrentCapacity` (percent), `IsCharging`, `ExternalConnected`, `CycleCount`, `Amperage` × `Voltage` ÷ 10⁶ for watts, `AppleRawMaxCapacity` ÷ `DesignCapacity` for health, `Temperature` ÷ 100 for °C. `nil` if the service is absent.
- [ ] **Step 8: `ProcessSource`** — `proc_listallpids`, then `proc_pid_rusage(RUSAGE_INFO_V4)` for CPU time and `ri_phys_footprint`; CPU = Δ(user + system time) ÷ elapsed, converted from Mach time units with `mach_timebase_info`. Name from `proc_name`. A pid whose rusage call fails is skipped (Review Focus 5). Forget previous times for pids no longer listed.
- [ ] **Step 9: Commit** — `feat: hardware sources`
